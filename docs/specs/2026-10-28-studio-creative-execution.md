# Studio 创作能力的具体模型执行契约

- 日期：2026-10-28。
- 状态：本地实现与替身集成验证通过；生产服务、真实供应商及模型品质仍未验收。
- 范围：主计划 [T03／T10](../plans/2026-10-27-studio-creative-team) 的模型请求、SDK 接线及执行前提。作者采用和项目写入仍遵循[采用协议](./2026-10-27-studio-creative-adoption)。

## 受信请求与 SDK 限制

制作组的七项能力继续由 Runtime 的登记实现生成模型请求：导演制作计划、人物设计、章节、美术方案、配音方案、试玩方案和导演交付建议。普通客户端不能指定模型、执行版本、调用上限或供应商凭证。

实际模型 SDK 除提示词、输出上限与温度外，还要求 `promptVersion`、`parserVersion`、`safetyVersion` 和 `executorVersion` 四个字段。创作请求原先缺少后两个字段，而且执行时间及编剧输出上限超过 SDK 默认限制，因而会在供应商调用前失败。修复保留已有 180 秒执行期限及 16,000 token 章节容量，并登记精确匹配版本元组的受信执行配置。

| 项目 | 创作请求 | SDK 默认请求 |
| --- | --- | --- |
| 提示词版本 | `advjs-creative-team-2026-10-27-v7` | 沿用各自登记版本 |
| 解析版本 | `advjs-creative-output-v6` | 沿用各自登记版本 |
| 安全版本 | `authoring-safety-v1` | 沿用各自登记版本 |
| 执行版本 | `advjs-creative-model-executor-v1` | 沿用各自登记版本 |
| 超时上限 | 180,000 ms | 120,000 ms |
| 输出上限 | 编剧 16,000 token，其他创作能力 8,000 token | 8,192 token |

SDK 的受信配置只匹配全部四个版本字段；任一不符时仍使用默认限制。配置在构造时复制固定，重复版本元组、非法数值或超出硬上限的配置被拒绝。请求中额外传入“覆盖限制”字段也被拒绝。模型目标允许清单、动态目标判断、服务身份及视觉模型检查继续独立生效；登记配置不会启用能力或改变价格。

`YunLeFun/api` 的 `createAdvjsModelSdkClient` 统一安装这份配置，收敛 HTTP 入口、生产 active Worker 和 production-public Worker 均使用它。普通聊天、写作和旧五能力沿用原请求版本与默认限制。提示词正文和产物解析规则没有变化；新的执行版本与安全字段随任务执行计划冻结，历史任务不倒填新字段或改写请求。

## Worker 与计费前提

显式开启制作组的 production-public Worker 默认租期为 240,000 ms；明确配置的租期至少为 210,000 ms，覆盖 180 秒期限及 30 秒余量。未开启制作组时仍使用原 120,000 ms 默认值。SDK 配置和能力登记均不会打开制作组开关。

启用生产流程前仍须核对 HTTP、Worker 和恢复任务的版本及开关，实际模型对 16,000 输出 token 的支持、云函数总执行时限、队列和预占有效期，以及各能力价格快照对最大请求的覆盖。本地 SDK 接受请求不能证明这些线上条件已经满足。

收费继续通过原任务引擎预占和按实际使用量结算。模型请求最多自动执行一次。结构化输出截断或解析失败时保留已确认的供应商用量与成本，释放用户预占；原任务重放不能生成第二次调用或重复结算。未知结果继续进入既有对账流程。

## 可执行验证与证据范围

配套 Runtime 中执行：

```bash
pnpm test:ai-runtime
pnpm typecheck:ai-runtime
```

新增集成测试逐项运行七项登记能力，经实际任务引擎、worker、`ModelExecutionBackend`、具体 `CloudBaseModelSdkClient` 和产品输出解析器，核对请求容量、超时、版本、完成及结算，再重放同一 worker 事件。额外覆盖精确配置匹配、默认限制、模型／身份拒绝、关闭能力、截断输出费用和制作组 Worker 租期。

测试只在第三方模型接口、身份、数据库与账本使用明确替身，没有收费模型调用；七项独立传输回归不构成一部完整六角色作品。实际结果见[验收记录](../reports/2026-10-27-studio-creative-team-acceptance)。

## 隔离项目工具与强单 Agent 对照

`@advjs/agent/evaluation` 提供独立评测入口，未进入普通浏览器客户端的默认导出。`createCreativeEvaluationWorkspace` 在内存副本执行与产品共用的源路径权限、完整写前内容核对、原子叠加、实际项目编译和核心试玩；不写作者文件、不执行宿主代码、不生成媒体。固定 v2 输入仍按原字节保存。所有模式应复用这组工具；最终审计独立执行冻结的两个选择路径，模型提出的路径不能替换它。

`createCreativeSingleAgentEvaluator` 当前支持 A／B：A 仅生成一次完整修改建议；B 由一个 Agent 连续规划、读取隔离源、修改、编译、自检和修订。每条回复及工具观察均保留，没有重启角色或用多个独立专家调用冒充单 Agent。B 最多 24 个自身工作项，每项初稿后可返工两轮；最多 72 次模型调用及 128 次工具调用，仍受同一总 token、费用和期限约束，不强行用尽预算。SDK 只接受 32 条原生消息时，将早期消息的完整角色和原文编码为显式历史，保留最新消息；不摘要、不丢弃内容。

单 Agent 与制作组共用 `CREATIVE_AUTHORING_GUIDANCE`，包含真实对白／旁白语法、稳定配音来源及成对剧情引文规则。提取公共知识后七项现有制作组提示词的字节哈希保持一致，仍为 v7／v6。单 Agent 的工具动作版本另为 `advjs-creative-evaluation-single-v1`／`advjs-creative-evaluation-action-v1`，执行版本为 `advjs-creative-evaluation-model-v1`。非文件方案可保留在摘要，未制作的图片和配音必须如实记录；头部无媒体输入，不能认证实际播放或表演。

执行返回 `completed` 仅表示执行结束且独立编译／指定路径通过。原始任务的语义要求保留 `unreviewed`，不以模型总结代替作者盲评。生成质量、系统拒绝、取消及未知供应商结果分别处理；未知结果抛出并保留未完成日记，不填造零费用或自动重试。

## 服务端模型绑定与预检

`@yunlefun/ai-runtime-advjs/creative-evaluation` 的 `createCreativeEvaluationModel` 使用实际 `CloudBaseModelSdkClient`、模型执行后端和价格计算，只在显式服务端子入口提供。它不登记新的生产能力，不启用账号额度或真实用户账本。调用方提供受信服务身份、允许的模型目标、冻结价格、实际 Runtime 版本，以及已针对该模型核验的消息框架 token 上界；输出上限须已确认包含推理 token。缺少真实核验时不能把本地预检当作供应商支持证明。

每次派发前，以 UTF-8 字节数及已核验的框架上界保守核算输入，预留完整输出；费用取所有价格档位／时段及缓存／推理桶的最大费率并覆盖分别取整。根据剩余总 token、费用和时间收缩本次上限，最大仍为 16,000 token／180 秒，给宿主收尾保留一秒。保守上界可能使尚未实际用尽的预算提前停止，须原样报告，不能补造调用或在比较中隐藏。所有实际供应商用量和费用均由后端返回；总 token 单独记录，不能只检查输入／输出之和。种子目前是独立尝试标签，未作为供应商采样 seed 下发，不承诺逐字重现。

受信绑定模块导出 `createEvaluationModel()`，在服务端组装上述调用器；身份和凭证不进入项目、版本 JSON、浏览器包或结果。`packages/agent/scripts/creative-single-evaluation-adapter.mjs` 从绝对路径环境变量 `ADVJS_CREATIVE_EVALUATION_BINDING` 读取它。配置尚未选定时明确失败，不能借用旧浏览器 BYOK 路径。

默认命令仍只做免费输入／预算计划审计：

```bash
pnpm --filter @advjs/agent build
node packages/agent/scripts/run-creative-evaluation.mjs --cases=local-01,short-story-01 --modes=A,B --seeds=1729
```

配置已核实的绑定后可使用 `--preflight`，同时传入绝对路径 `--adapter` 和 `--versions`。版本配置的 `model`／`prompts`／`tools`／`runtime` 必须与适配器描述匹配，`project` 是冻结根项目文件图的实际 `computeAgentProjectRevision`，而非文件名。免费预检不创建运行日记或调用模型；`ready` 只表示绑定与版本静态匹配，不认证线上身份、容量或创作品质。预检与 `--execute` 互斥；真实收费执行还需要另行明确的预算授权。

执行器持有独占 `.evaluation.lock`，派发前写入并同步运行日记；每次模型意图、原始回复、用量、工具结果和最终源／审计另以独占 JSON 文件保存并同步，禁止覆盖旧证据。同一已结束执行不会重复派发；未知结果、超限或输入／适配器指纹变化必须先核对。遗留锁不会自动删除，先检查记录中的 PID、实际进程、运行日记及供应商回执，不能仅以锁文件推断进程仍活跃。

## 对照评测与尚未完成事项

A／B 已有隔离工具、连续上下文执行器和具体 SDK 调用器的本地接线；当前 C 明确拒绝执行，仍须接入真实制作组的登记能力、预算、顺序编排、候选选择及独立试玩流程，不能以静态专家回复补位。共同模型、价格和框架上界的真实配置尚未选定，实际收费试跑、整部六角色作品与作者盲评均未完成。固定 v2 输入没有改写，品质、费用和延迟门槛继续以主计划为准。
