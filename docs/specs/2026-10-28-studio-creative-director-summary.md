# Studio 导演交付建议

- 日期：2026-10-28。
- 状态：部分实施；已接通本地受控能力、冻结交接、只读建议与独立作者收尾。真实模型的创作判断、完整六角色作品及生产服务尚未验收。
- 范围：[主计划 T03／T04／T09／T10](../plans/2026-10-27-studio-creative-team)。实际验证记录见[验收报告](../reports/2026-10-27-studio-creative-team-acceptance)。

导演根据作者已选的实际成果给出评价、风险和下一步建议。生成建议复用原任务引擎与预算；作者仍须独立审阅范围并决定结束制作组。结束决定与免费的历史回执以[采用规格](./2026-10-27-studio-creative-adoption)为准。

## 能力与触发

新增 `director/summarize-production`，产物为 `delivery-summary`。创作伙伴仍为六位，登记的制作组能力由六项增为七项；旧五项能力及其 v1／v2 协议保留。当前提示词为 `advjs-creative-team-2026-10-27-v6`，解析版本为 `advjs-creative-output-v5`。

导演计划可安排一个交付建议任务，必须位于所有其他任务之后，不能有下游任务。提示词要求导演统筹的制作计划安排此任务；计划校验只限制已安排的任务，不给单角色请求隐式追加调用。作者审阅计划时确认是否需要总结。

即使前置成果均已选定，此任务也不会自动执行。Studio 在能力实际可用且状态允许时显示“生成导演交付建议”；作者点击后复用既有 `request-rework` 决定及幂等键，首次触发不新增公开动作。后续重新汇总受原 `maxReworkRounds` 限制，全部调用受剩余预算与工具调用上限约束。

触发条件要求没有在途或待对账任务、没有待审的其他任务、没有仍可调度的普通任务、没有准备中的里程碑与未释放预占，且制作组未结束或取消。失败任务或因依赖无法运行的待办可以进入部分成果总结，保留真实状态，不将它们伪装为完成。作者可以继续修订或直接按已有规则审阅当前范围。

## 冻结来源与执行事实

Runtime 在接受明确请求时保存 `summary:<taskId>:<attempt>` 交接，实际模型调度继续使用既有 outbox。报价前重新核对实际源、选定成果和执行状态；交接过期则拒绝调度，不创建这次模型费用。

交接包含：

- 完整保存源及已选候选的有限差异，合成为本次有效快照；已采用的文件不重复应用。
- 所有已选／已采用的非总结成果 ID、指纹、负责角色、任务 ID、类型与状态。
- 其他任务的职责、指令、预期产物、依赖、真实状态、尝试次数、已结费用与错误。
- 待审候选、里程碑、截至本次总结前的已结费用及工具调用数、尚未满足的素材请求。
- 已保存作者宿主试玩报告的来源版本、范围和结果；报告缺失时明确标记，不能由模型补出。

模型读取一份有效项目快照。`advisoryBriefs` 单独保留已选视觉方案、配音选角／表演／词典、逐句指示、试玩计划以及没有源变更的旧能力建议；逐句对白只保留路径、稳定身份、物理范围与指示，完整对白从实际源读取，避免重复复制整章和源块。它们是创作意见，不授予执行或认证权限。简报有数量、大小及成果指纹校验，最终仍受原任务输入上限约束。

试玩事实从服务端实际保存的完整报告读取，经原严格解析器验证后投影指定场景、选择输入、状态、实际结局、终止位置、命令数和诊断。报告和运行摘要的项目、源版本、成果引用、各状态数量不一致时拒绝；没有完整报告时标记不可用。保留 `author-host` 来源，不能称为服务端重放认证。

## 模型产物与作者审阅

模型只能填写：

```ts
interface DirectorAdvice {
  kind: 'delivery-summary'
  summary: string
  overview: string
  deliverables: Array<{ artifactId: string, fingerprint: string, assessment: string }>
  risks: string[]
  nextSteps: string[]
  recommendation: 'continue-creation' | 'review-current-scope'
}
```

`deliverables` 必须逐项覆盖全部冻结的已选／已采用成果，拒绝虚构引用、遗漏、重复及额外执行字段。Runtime 注入只读 `evidence`；模型不能改变费用、成功状态、来源或实际结果。内部重复解析只允许与冻结证据相同的元数据。

Studio 只读显示建议、实际成果、汇总前费用、待办及已保存报告。它区分本次有效快照与报告的源版本，明确指出当前总结自身费用另行结算；叙事品质、画面、声音和未覆盖路径仍需验收。选定总结只保留建议，制作组保持待审，不写项目、不创建作者完成回执。刷新和重开仅读取已有结果。

## 过期、费用与有限返工

源内容或文件集合、已选成果、其他任务状态、里程碑或实际报告变化会使总结过期。总结自己的完成、费用结算与选定不使它自身过期；已发生的费用保留在真实账本中。新报告在总结执行期间到达时，返回的旧建议仍会过期。

作者重新汇总时，新的“汇总前费用”包含此前总结调用的实际费用。已经过期的旧成果不能再次撤销作者已接受的新返工请求；导演重试的刷新只传播新发生的过期，普通任务原有来源失效规则保留。达到返工上限、结算未知或预算不足时，原有阻塞与对账规则继续生效。

## 验证与边界

Agent 回归覆盖明确触发、终端依赖、冻结事实及指纹、模型越权拒绝、自身结算、真实报告投影、报告缺失、执行期间新报告导致过期，以及保留费用的有限重试。Runtime 回归覆盖交接构建和受控模型输入；HTTP 回归通过实际任务引擎、worker 完成、账本与独立作者收尾，模型输出使用明确替身。

浏览器用例用实际项目文件、编译器和核心运行时执行两个指定结局，再手动生成、审阅和重开导演建议，最后独立结束制作组；替身结果不代表真实模型质量。正式能力策略与托管媒体开关保持原状态，未进行生产部署、付费调用或原生 iOS 执行。
