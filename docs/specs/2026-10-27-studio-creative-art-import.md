# Studio 美术方案的本机图片回流

- 日期：2026-10-27。
- 状态：部分实施；本机候选、原始字节核验、Catalog／绑定审阅、事务采用、恢复和条件撤销已接入，默认立绘、表情和背景已用既有真实图片在 Web 正式试玩组件中逐项采用、重开与显示。新服务路径已连接不可变媒体登记及统一里程碑；生产、跨设备接续与真实六角色美术质量尚未验收。
- 范围：[主计划 T06／T09](../plans/2026-10-27-studio-creative-team) 的人工图片回流；实际证据见[验收记录](../reports/2026-10-27-studio-creative-team-acceptance)。

## 交互与来源

作者从已选定美术方案的稳定 `assetId` 选择需求，提供文件、来源与可选内容许可。支持 PNG、JPEG、WebP，单张最多 20 MiB；按文件签名识别格式，通过浏览器真实解码取得尺寸，并计算原始字节 SHA-256。文件扩展名、调用方 MIME 和模型 URL 不授予媒体采用权限。尺寸上限为单边 16,384、总计 64,000,000 像素；实际尺寸与方案不同时明确显示，采用保留原图尺寸。

候选私有存储于 `advjs-studio-creative-art-imports`，按账号、项目和制作组隔离，保留具体方案指纹、需求、图片指纹和来源说明。未确认采用的二进制与恢复记录不写进游戏源码。每个作用域最多 32 条图片记录；与配音候选共享未完成二进制合计 64 MiB 的限制；作者可明确移除候选记录。采用并核对项目字节后清除私有候选中的冗余二进制，项目原图仍保留。

## 目录与绑定

复用 `planAdvAssetManifestUpsert`，唯一可写根仍为 `adv/assets.json`；支持内联与分片目录，保留既有本地根和远端 Profile。原图按内容哈希命名，使用相对路径；目录记录 MIME、真实尺寸、字节数、来源及许可，不把暂时的 Blob URL 写进项目。

角色与表情使用既有 Catalog `kind: character`、`characterId`、`expression` 绑定；默认画像为 `default`，人物档案须已采用且稳定 ID 存在。背景使用场景卡的 `assetId`，必要时创建对应 Scene；Location 继续仅为关联地点，不替代 Scene。更新场景前置字段时保留未知字段与正文，旧 `src` 由明确审阅的稳定 ID 引用取代。

同一个角色／表情已有另一资源 ID 时拒绝隐式覆盖。替换相同资源 ID 的不同内容需作者选择“审阅同 ID 替换”。Review 展示每个目录与场景文件的完整写前／写后内容，并编译候选项目；未知人物、场景或资源冲突必须先处理。旧 `adv/assets/index.json` 不由此入口隐式迁移。

## 已保存项目的素材核对

“项目图片核对”逐项检查已选定、已采用及过期美术方案中的需求，读取当前共享文件系统的实际源文件和图片。清单区分项目缺少素材、方案来源变化、资源绑定不匹配、图片缺失／损坏／元数据不符及绑定与字节匹配。私有候选尚未采用时仍显示缺少项目素材；匹配只说明绑定及解码字节符合目录，不代表美术品质、来源权利或供应商认证。

检查复用共享编译器、目录路径解析和真实图片检查器；角色／场景绑定规则与统一媒体采用共用。核对目录记录的 SHA-256、字节数、MIME 和实际解码尺寸，展示项目来源版本，路径与图片指纹可展开。项目编译错误单独显示诊断，不把局部匹配升级为整项目可用。

读取等待本机项目写队列与文件操作结束，捕获来源版本和文件变更序号，异步解码后再次核对；读取中有修改则丢弃结果。文件写入、跨窗口变更提示、任务版本变化以及窗口恢复均清除旧清单，作者需重新点击检查。核对不写项目，不请求模型，也不自动重试采用。

共享编译器识别 Catalog 的 `kind: character` 图片及其 `expression`，按角色 ID、名称和别名校验立绘指令，同时兼容原 `kind: tachie`。游戏背景组件挂载时读取已有背景切换事件，避免首帧指令早于组件挂载而留下黑屏。2026-10-29 回归使用不同字节的默认立绘与 `good` 表情；原图尺寸差异继续明确显示并保留。多份图片同时改写同一目录分片时，现有入口要求逐项采用和重新核对，不隐式合并媒体绑定。

## 写入、恢复与撤销

服务声明 `authoring.mediaCandidates` 后，导入口先持久化请求与幂等键，再登记不可变制作组媒体候选；此时项目仍不变。未知响应只能用原请求重试。正式写入、恢复和条件撤销交给统一“采用到项目”区域，可与不同源文件的配音候选一起审阅；详见[采用规格](./2026-10-27-studio-creative-adoption)。卡片说明 `author-host` 核验来源并展示资源、路径、真实字节数和哈希，不能当作供应商认证。未升级服务和原本机记录保留既有本机流程。

确认采用前持久化本机操作意图。实际写入复用 `commitStudioProjectFiles` 的项目锁、逐文件 CAS、全项目版本核对和持久化屏障，将图片、目录和场景绑定作为同一次原生工作区操作；失败补偿遵循[采用协议](./2026-10-27-studio-creative-adoption#非原子文件后端的失败补偿)，仅处理仍可确认属于本轮的文件，保留外来新稿与未知状态。已存在的相同路径必须通过字节核验，损坏或被作者替换的文件不会被覆盖。

媒体的持久化意图和部分写入判断现与配音共用[中断恢复协议](./2026-10-27-studio-creative-media-recovery)，保留原图片表并原位升级。存在待恢复图片或配音意图时，两个导入口在同一存储事务内阻止新项目写入。

后端在写完二进制后才报错时，只有保存源可核对且原始字节仍匹配本次导入，才回收新增文件；写入前就失败时不尝试删除不存在的文件。保存事实、方案身份和作用域在异步操作边界重复核对，切账号／项目／制作组丢弃迟到候选，方案版本改变则阻止旧采用。

重开只读取项目和意图，不自动再次采用，也不发出生成请求。写后记录尚未确认时，核对实际源码版本与图片字节：写前可以明确继续或放弃；写后仅确认本机记录；目标文件为已审阅两版本的混合且其他源未变时，作者可明确继续或恢复写前内容；作者改动或未知媒体则保留资料，禁止自动覆盖。撤销要求项目仍与采用后的精确版本一致，恢复目录与绑定的原始文本，不删除可复用的原图。作者中途保存文件后，自动撤销被阻止。

## 已验证与尚未交付

Web 浏览器实际导入仓库已有的小云 WebP（619 × 619），核对预览、候选重开、采用前正式文件不变、采用后的字节／目录一致、重开恢复和条件撤销。再次采用后离开 fixture，打开正式 `/tabs/play`，由实际 `GamePlayer` 和目录适配器读取项目 Blob 并显示角色图片。美术方案、账号与任务历史为明确 fixture；这张既有素材不是新生成的雨夜车站美术品质样本。

桌面／窄屏审阅与正式播放器截图分别检查，窄屏工具栏的次要操作收进菜单，宿主运行时检查器与游戏菜单分开摆放。截图保留实际游戏动画并在视口变化后核对图片已加载、可见和进入视口，避免截图工具关闭动画产生空白证据。

新服务路径已连接制作组不可变候选、统一里程碑和采用锚点；服务确认后才记录采用并释放私有冗余字节，任务／运行不会因此自动完成。2026-10-29 又以既有真实默认立绘、不同字节的 good 表情及背景，分别完成统一里程碑采用、IndexedDB 只读重开和正式 GamePlayer 显示；两种浏览器逐一核对实际显示字节，并验证缺失、损坏与来源过期清单。真实服务方案质量、风格一致性、全部媒体下游传播、跨设备接续、Capacitor／原生 SwiftUI、图片托管生成仍需独立验收；配音的部分闭环另见[真实对白回流规格](./2026-10-27-studio-creative-voice-import)。T06／T09／T10 保持未完成。
