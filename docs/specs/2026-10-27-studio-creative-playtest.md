## 执行与证据边界

模型只能提出 `playtest-plan`：指定结局、零起始选择序列和待核实疑点。实际报告独立存储为 `CreativePlaytestReport`，不属于模型产物，不因模型自述而完成任务。

`runCreativePlaytest` 从已保存源文件或精确选定的候选版本编译项目。候选只在内存中覆盖，核对来源、上游指纹与同文件冲突；不写正式文件，不替代采用。每条路径创建独立 `createAdvRuntime`，仅执行 `start`、`next` 和指定可见选择的 `choose`，不跳转到目标结局，也不伪造宿主交互结果。内置变量动作使用当前项目的初始变量；不载入外部插件或执行宿主副作用。

报告保存实际快照指纹、程序 ID／hash、完整复现输入、实际指令、状态、文本、进入的节点、选择 ID／序号／标签、变量变化的键和效果类型。静态诊断独立列出，模型提出的疑点标为未核实。

“指定路径通过”要求指定选择全部消耗、实际运行终止，并能从预期结局位置沿无歧义的同章尾部到达终止节点。遇到其他标题、分支或跨章跳转时，不仅凭“曾到过该标题”判定通过。报告保留 `reachedExpected`、实际终止地址和失败原因，不强行修正输入或偷换入口。

编译器新增的节点源映射保存在编译结果中，位于程序及其 hash 之外。Markdown 保留真实行列并映射合并源文件；Flow 当前只知道文件，报告不虚构每个 JSON 节点的行号。源位置按钮使用现有文件编辑器的 `file`／`line`／`column` 路由。

## 上限与未覆盖内容

| 项目 | 当前上限或行为 |
| --- | --- |
| 输入快照 | 沿用 48 KiB 文本、256 文件的创作请求范围；验证指纹。 |
| 路径与选择 | 最多 12 条；每条最多 32 次选择，序号 0–31。 |
| 核心指令 | 默认每条最多 256 条，所有路径合计 512 条；限额前停止，不能标为通过。 |
| 轨迹 | 最多 192 KiB；容量不足明确阻塞，不用截断后的轨迹宣称通过。 |
| 静态诊断 | 最多 32 KiB、128 条；优先错误，注明未保存条数。 |
| 报告 | JSON 最多 256 KiB；解析器检查预算、序列、终止证据及固定未验证声明。 |
| 服务端历史 | 每次运行最多保存 32 份，单独控制行保存报告和冻结输入，运行元数据只放摘要引用。 |

报告固定标明：画面渲染、音频播放、宿主交互、剧情一致性和其他路径未验证。效果中出现 `dialogue.voice` 只表示核心发出了请求，不证明音频存在、已采用或已播放。插件不可用、选择不足、运行错误、取消和容量用尽都保留实际阻塞／失败状态。

## 作者宿主报告的保存

新增服务声明 `authoring.playtestReports`。报告通过已有鉴权、应用 audience、Origin 和限流路径保存；账号、项目和运行决定可访问范围。服务检查来源指纹、候选身份、快照派生、源行范围、报告格式与预算，并以请求键保证幂等；相同键的不同内容报冲突。

服务将其标为 `verification: author-host`，**没有在服务端重放或认证执行结果**。所验证的格式及来源不等于平台已验证路径品质。报告不能修改正式事实、完成角色／制作组、扩大预算、扣点或生成媒体。

报告 POST 的默认 HTTP 上限为 640 KiB，容纳有界报告和可能需要 JSON 转义的冻结源文件；其他任务路由保留 64 KiB。显式设置的全局请求限制仍生效。报告和冻结源文件在单独的存储行中保留，不重复塞入每次运行读取的元数据。

本机使用独立 IndexedDB 数据库 `advjs-studio-creative-playtests`，按账号／项目／运行／请求键保存报告和复现输入，不进入项目导出。存储失败时不承诺重开恢复，也不继续自动同步。同步响应不明时保留同一请求键，重开只读取，作者可以明确重试。

## 过期与复测

执行、打开报告和明确核对版本时重新读取当前项目；源读取及 hash 完成后均核对账号和项目。切换作用域时停止本机执行，丢弃迟到的源读取、报告和同步结果。

核对版本时，当前源须匹配报告的写前基线或候选快照；候选 ID／指纹仍须处于选定或已采用状态。否则报告只作历史证据，不代表当前项目通过。复测载入原报告的选择输入，然后明确执行当前快照，不自动还原旧文件或覆盖作者修改。

采用版本锚点还覆盖本次成果引用的已批准祖先，避免导演计划因自身后续成果采用而过期并反过来污染整条链路；不会因此锚定祖先的所有独立分支。

## 本地验证与剩余要求

本地实际执行覆盖：双结局选择、错误分支、缺失／未用完的选择、悬空引用、不可达章节、指令与轨迹上限、取消、点号地址、原生人物对白、候选隔离、过期和修复后复测。浏览器验证真实核心执行、IndexedDB 恢复、无 POST 重开、报告同步和源定位路由；其身份／历史服务是醒目标注的 fixture，未使用生产模型。

固定 v2 输入可证明选择路径，不作为人物对白绑定或 VoiceTake 验收输入；原生对白另有 `@lin` 编译与核心效果回归。浏览器 fixture 的源定位检查验证路由参数，未挂载正式文件编辑器；真实服务中的整段编辑器导航仍需集成验收。

媒体回流与实际 Web 播放已有各自的有限验证，不能由本报告推断。缺失／未选／过期配音与原文件缺失的独立样本覆盖 Markdown 和 Flow，剧情疑点的成对来源及明确作者核对另见下节，来源及范围见验收记录。尚未完成：真实六角色服务短篇、整部作品的媒体验收、剧情检出／误报与修复质量的真实评测、宿主交互与原生 iOS 接入、服务端重放认证、同预算质量对照和作者盲评。当前报告不能替代这些门槛。

## 按实际报告交还负责人

作者可以选择已同步、源版本仍匹配的报告问题与负责的编剧、角色设计、美术或配音任务。此操作明确执行一次原任务的有限返工；导演／试玩员不充当素材修复负责人。没有问题、仅存在未核实模型疑点、选择输入不足、取消、容量限制或未验证媒体时，不将这些状态当作源码修复证据。

`request-rework` 可携带 `playtestRepair: { reportId, snapshotRevision, findingId }`。调用方不能提供完整问题、源内容、费用或通过回执；Runtime 从账号／项目／运行内已保存的不可变报告提取实际诊断或失败路径，核对报告版本、当前保存版本和选定候选。引用与负责任务保留在作者决定、任务状态及结算后的尝试历史中。

冻结交接先于旧候选过期。保存事实、实际测试的候选文本及其差异分开保留；负责人能看到原候选中的错误，而生成结果的写入基线仍来自真实保存事实。私有冻结交接使用现有分行存储；不把源码复制到公开任务状态。交接的反馈仍受 4,000 字符限制，完整能力请求保留原有容量限制。

报告问题编号基于不可变报告中的位置；通过路径、作者选择不足或超限不列为可修复失败路径。问题与报告均是作者宿主证据，没有升级为服务端重放认证。作者选择负责人，不声称已经自动判断根因或完成修复。

Studio 根据报告 ID、任务 ID 和问题 ID 生成稳定意图键；响应不明时重开只读，明确重试仍使用同一键。同一键改换内容被拒绝；同一份问题如需再次返工，应先执行当前版本得到新报告。重新派发前核对保存来源和上游版本；来源改变时保留过期／阻塞状态。报价期间来源改变且任务元数据未变时，也不会预占旧交接。

新能力通过 `authoring.playtestRepair` 单独发现；旧服务没有声明时不会开放按钮。返工复用原预算、单任务限制、返工次数、持久化 outbox、取消与真实结算，不追加收费通道。新候选仍需作者审阅，随后载入原报告输入，对当前候选或采用后的项目明确复测；不自动采用或改写原报告。

本地浏览器验收已实际完成“编辑候选植入悬空引用 → 核心诊断 → 选择编剧 → 返回修复候选 → 审阅选定 → 同输入复测通过 → 重开只读”。身份、负责人回复和历史服务是明确标注的 fixture，编译、候选事务、核心执行与 IndexedDB 为实际实现；没有真实模型修复质量或生产服务验收结论。


## 同快照的作者宿主配音证据

`voiceCoverage` 是可选的宿主检查记录，与核心 `executions` 分开保存。受信工作区回调读取实际执行的保存／候选快照，复用完整编译对白清单、发音词典、人物与独立旁白 Profile、VoiceLedger 和实际项目文件的 SHA-256 核对。运行器提供有效快照；宿主在检查前后核对保存基线、账号与项目，读取期间改稿或切换作用域则丢弃迟到结果，不写游戏文件或请求模型。

每行记录真实运行时地址、已有稳定台词身份、说话者、源位置、候选数量与状态。状态包括缺少配音、已有候选未选用、已选过期、原文件缺失／损坏、原文件字节匹配和稳定身份不明确；已选行还冻结当时的 take ID、资源 ID 与 SHA-256。没有可用音色另作提示，人工录音仍可具有匹配原文件。Flow 不猜造 JSON 物理行号。检查涵盖编译结果中的对白及独立旁白，不依赖配音导演方案是否列出，也不要求核心路径已经走到该节点。

核心路径可以通过，同时存在缺失配音。没有检查回调、项目无法编译或旧报告没有该字段时，界面明确显示未检查；`dialogue.voice` 效果不能替代原文件检查。原固定 `unverified` 声明保留，字节匹配不证明实际播放、表演品质或服务端媒体认证。这是报告生成时的历史观察；重新打开只读，后续原文件变化须重新检查。

配音字段最多保存 128 行、16 KiB，问题行优先，`rowsOmitted` 明确指出因容量省略的行，不把省略内容算作通过。`complete` 表示编译清单是否完整；有省略时不能据保留行数推断整部作品已覆盖。报告继续遵守总 256 KiB 上限。

服务通过 `authoring.playtestVoiceCoverage` 单独声明兼容性。只有明确支持时，Studio 才把此字段随报告同步；不支持报告同步的本机流程仍可检查并保存私有记录。已有配音证据在旧服务上重试时保留原报告，显示能力不支持，不静默剥离证据或提交不兼容请求。原无此字段的报告与服务协议保持兼容。

存储端解析字段、状态、容量、快照与重复引用，核对源文件、行范围及已有台词身份字面来源，拒绝伪造服务认证或跨快照元数据。它仍是受鉴权的作者宿主报告，服务没有读取本机媒体或重新执行检查。保存、重开及同键重放不产生模型任务或额外费用。导演交付建议从真实已保存报告读取这份证据；模型不能替换冻结记录。

### 配音问题交还负责人

缺失、未选、过期、原文件不可用与身份不明确的保留行可形成 `voice:<index>` 问题引用。未执行的检查和字节匹配行不生成配音失败问题。作者明确选择负责人后，仍走既有有限 `request-rework`、预算、来源检查、幂等与未知结算规则；交接补充原快照内的音频设置、词典、人物和资源元数据。原文件字节不进入模型输入。

模型只能提出修订或制作建议，不能因此制造 VoiceTake、成功回执或声称已播放。身份问题可交给编剧准备，配音制作仍经既有音色／外部录音、导入、试听、独立选用和采用流程；修复后以同一复现输入显式执行当前快照并重新读取媒体。

## 剧情疑点的成对来源与作者判断

试玩员沿用 `playtest-project` 的 `playtest-plan.concerns` 提出解释；不新增一个自动宣判剧情正确的能力。新提示词／解析版本为 v7／v6。每项疑点可提供 `evidence.expected` 与 `evidence.actual`，分别引用建立预期的设定和待检查正文：`path`、从完整文件首行计数的 `line`／`endLine`、完整物理行的 `text`。每段最多 32 行／4,000 字符，只规范 CRLF 为 LF，不删前缀、格式或身份标记；实际正文引文的起始位置须等于疑点顶层位置。服务解析模型产物时逐字核对冻结有效源，拒绝补造、越界或改写的引文。

引用路径可以是世界观、人物、Markdown 或 Flow 源文件。Flow 此处引用原始 JSON 物理行，不冒充稳定对白身份；重新排版也会改变引用。旧方案没有成对引文仍可只读展示，标为未核实，不能直接确认成有来源支持的问题。引文匹配只能证明引用真实，不能证明模型的冲突解释正确；人物猜测、不可靠叙述、条件分支、设定允许的例外或作品中的虚构内容都可能形成误报。

### 独立的作者核对

作者明确勾选“随本次报告保存剧情核对”，对照两段引文，逐项保留待核对、确认需要修改或排除疑点。确认／排除均须写明理由，默认不确认任何项。切换提案或保存／候选范围会清除旧核对选择；执行时按真实有效源重新核对，源已变化或提案失效则拒绝保存旧确认。账号／项目切换及执行期间改稿仍丢弃迟到结果。核对与核心路径执行不请求模型、不写游戏文件。

实际报告的可选 `narrativeReview` 保存当时的快照、试玩提案 ID／指纹，以及保留行的原疑点索引、解释、成对引文、来源状态和明确作者判断／理由。来源状态为 `matched`、`unanchored` 或 `changed`；只有匹配的成对引文可以带有确认判断。每份最多 32 项／16 KiB，容量省略以 `rowsOmitted` 明确计数，不能把省略项视作通过。附带该字段时默认轨迹预算收紧到 176 KiB，原报告总 256 KiB 上限保留。核心路径通过和剧情问题可同时成立；原 `narrative-consistency` 未验证声明不删除，不据局部确认、排除或空列表证明整部作品一致。

服务通过 `authoring.playtestNarrativeReview` 声明支持。新客户端读取无此字段的旧报告；待同步报告遇到不支持的服务时保留完整本地证据，阻止不兼容上传，不删除判断。服务保存时再次核对不可变提案、原疑点、实际快照和字面来源，但不认证作者的语义判断。重开只读，不重新判断或改写历史引文。导演交付建议从实际已保存报告冻结这份记录，同样保留作者来源与未完成范围。

### 负责人返工与再次检查

仅保留行中 `matched` 且作者明确 `confirmed` 的疑点提供 `narrative:<原索引>` 返工引用；待核对、已排除、来源失配及省略项不生成已确认问题。作者另选负责人并触发现有有限返工；交接保存两处实际来源与作者理由，遵守原预算、次数、幂等及未知结算规则，不自动修改设定或采用修订。

负责人修订后，旧报告仍记录旧版本。作者可以明确请求试玩员针对新候选重新检查，再核对新疑点并以原选择输入重跑；核心复测通过本身不能证明剧情问题已修复。实际模型检出率、误报率、修复质量和整部作品的一致性仍需另行评测。本地验证使用明示的缺陷／误报语料和负责人回复替身；可证明真实源核对、作者动作、版本交接与核心复测，不能作为模型质量结果。
