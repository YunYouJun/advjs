## 方案与稳定台词

作者选定 `voice-direction` 后，在制作组核对实际对白。入口同时展示人物／独立旁白的音色和表演建议、发音词典建议，并将具体说话者和稳定 `lineId` 交给既有音色设计、配音任务、试听审阅页面。建议不自动写入 VoiceProfile 或发音词典，不发起生成任务；受审写回见下节。

## Flow 的稳定台词交接

新的 Flow 方案使用 `lines[].lineId`，取值必须是源 `*.chapter.json` 已存在的稳定台词身份；不使用 JSON 物理行号，不能同时提交 `line` 和 `lineId`。例如：

```json
{
  "path": "adv/chapters/intro.chapter.json",
  "lineId": "line_01900400-0000-7000-8000-000000000002",
  "speakerId": "lin",
  "text": "列车还没有到，我们再等一会儿。",
  "instruction": "平静地邀请同伴继续等待"
}
```

冻结来源检查解析实际 JSON，不依赖排版、行号或台词字符串在原文件中的字面位置。它在 `dialogues` 行或独立 `narration` 节点中核对唯一的 `lineId`、完整文本和稳定说话者；旧 `speaker` 字段、人物档案里的显式姓名／别名可精确核对，不模糊猜测。相同文本可以有不同身份；相同身份重复使用、原文／说话者不匹配或猜造 ID 都拒绝。旁白仍使用独立 narrator Profile。

Studio 还必须重新编译真实项目，核对节点类型、源路径、完整显示文本、稳定说话者和整个程序中的唯一台词身份。成功结果展示真实运行时地址，例如 `intro#start.dialog-2`；不会把第二句伪装为 JSON 的第 1 行。读取音频账本后再核对完整源版本，避免返回读取期间变化的混合快照。该源文件随后继续受既有采用锚点、事务版本检查和媒体核验保护。

新方案的解析、候选修订、媒体登记与独立选用共用这个来源约束。媒体登记将目标 take 的稳定 ID 与方案中的具体一句绑定；两句文字相同也不能把甲句的录音登记给乙句。旧单行 Markdown 方案保留 `line` 的兼容语法；登记时额外要求目标 ID 与该行的字面标记一致。历史 Flow 行号方案可以只读保留，但不从物理 JSON 行号推断身份；界面提示重新交接，或从完整对白清单进入既有配音任务／审阅。

Runtime 当前提示词版本为 `advjs-creative-team-2026-10-27-v6`，解析版本为 `advjs-creative-output-v5`，明确要求 Flow 复用源 ID，不能由模型创建成功回执或实际音色身份。共享冻结来源检查只是有限数据核对，实际编译、媒体解码与原始字节核验仍由作者宿主执行，不因此变成服务端媒体认证。

## Markdown 完整源块的稳定交接

多行对白和引用旁白使用源已存在的 `lineId`，并通过 `source` 引用完整 Markdown 节点的物理行；顶层不再填写旧式 `line`。例如，下面这一项对应章节第 3–5 行的完整 `@lin` 段落，覆盖格式装饰和最终身份标记：

```json
{
  "path": "adv/chapters/intro.adv.md",
  "lineId": "line_01900400-0000-7000-8000-000000000001",
  "source": {
    "line": 3,
    "endLine": 5,
    "text": "@lin\n列车还没有到，\n我们再**等一会儿**。 {#line_01900400-0000-7000-8000-000000000001}"
  },
  "speakerId": "lin",
  "text": "列车还没有到，\n我们再等一会儿。",
  "instruction": "完整段落的表演指示"
}
```

`source.line`／`endLine` 均含端点；对白从 `@` 指令行开始，引用旁白覆盖整个 `>` 节点，包括其中的多段落。`source.text` 必须是这些完整物理行的字面内容，只将 CRLF 规范为 LF，不改写缩进、装饰、空行或标记。它与编译后的显示 `text` 是两个字段：显示文本必须逐字匹配当前编译结果，包括编译器已有的段落及换行语义，不能把每行拼成一句、漏掉续行或按引用原文猜测渲染结果。现有解析器的显示语义保持不变。

共享校验核对冻结文件、范围、字面引用及块内的目标 ID；媒体登记还核对目标 take 的同一身份。服务不另写 Markdown 解析器，也不将有限来源核对称作真实编译。文件中代码示例提到同一字面标记，不等于另一个实际对白；最终由宿主编译器核对整程序的身份唯一性。

宿主检查节点类型、路径、稳定 ID、说话者、完整显示文本以及实际编译起止行；引用范围包含了正确 ID，但越过真实节点边界时仍拒绝。编译来源图保留 AST 的 `endLine`／`endColumn`，多文件章节将两端映射到原文件；无法映射为同一个真实源块时不能猜测。跨度只属于来源元数据，不进入执行程序或其内容哈希；持久化试玩报告仍显式映射已有点位置字段，保持原协议。

界面展示真实源范围、运行时地址及保留换行的完整显示文本；导入、独立选用、媒体字节及来源复核继续使用既有流程。采用不重写章节，修改任一续行后仍保留历史账本／take，通过实际编译文本和来源版本识别过期。独立旁白必须使用自己的 narrator Profile。

旧单行纯文本方案继续使用物理 `line`，不会替旧方案猜造多行范围或稳定 ID；新 Markdown ID 方案必须提供完整 `source`。Flow 不接受 Markdown 源块，仍仅按实际 JSON 的稳定 ID 交接。新模型请求使用上述 v5 提示词／v4 解析版本，旧快照仍按只读历史保留；模型不能生成媒体成功回执。

## 编剧候选的台词身份准备

编剧提示词示例使用实际 `@稳定人物ID` 对白与引用旁白，并提供入口和两个结局的完整章节及锚点。保留原台词的最终身份标记，新台词不由模型猜造 ID；普通“姓名：对白”仍按原语法编译为正文，不能冒充可配音对白。v5 只更新提示词，输出解析协议仍为 v4。

作者在章节候选编辑中执行“补齐台词身份”，宿主调用 `prepareMarkdownVoiceIdentities`，按真实 AST 仅对缺少身份的对白／旁白生成 UUIDv7。按 AST 原偏移插入最终标记，保留 Markdown 装饰、引用前缀、词条、空行和 LF／CRLF 字节；已有身份不会因改字或重复准备而重算。重新解析后，除位置及所加身份外的 AST 语义必须相同，每个新 ID 必须真正附着到原节点，不能落进被忽略的引用代码块。当前候选章节内已有重复身份、无效标记或无法安全插入时整次失败，原草稿保留。

该动作只编辑本机表单草稿，不发请求、不调用模型、不写项目。准备期间阻止并行表单提交；来源失效、草稿变化或结果超过每章 32,000 字符时不应用结果。改稿后准备结果提示消失，但正文中已有身份保留。作者仍须说明原因并保存独立候选修订，再选定和通过既有完整编译审阅采用。关闭／刷新前未保存的草稿遵循原候选表单行为，不承诺新增持久化；已保存修订随制作组历史重开。

准备范围只包含当前候选，不重写项目其他章节或 Flow 身份。整程序重复身份、人物引用及完整版本仍由采用／导入的实际编译检查；准备成功不表示音色已配置、VoiceTake 已制作或完整作品配音通过。新身份会成为实际程序数据，不能把它与不影响程序哈希的来源跨度混为一谈。

## 词典与声音意图的受审写回

服务声明 `authoring.voiceDirectionEdits` 后，人物和章节已有的不可变作者修订流程也支持配音方案。作者明确填写规范语言标签，编辑字面发音替换词条，按说话者勾选需要写回的声音意图。可修改年龄感、性别表达、气质、表演／说话风格、音高和语速；未填写字段保留原值。供应商、实际 voice ID、模型、已有授权和本机原音频不由该表单修改。

`voice-direction.locale` 是明确的写回语言，`cast[].intent` 仅允许上述供应商无关字段。旧方案未声明语言时仍只有文字建议。Runtime 从冻结源派生有限变换：合并 `adv/audio/pronunciation.json` 的对应语言词条，保留全局词条及其他语言；角色只修改其人物档案内的 `voiceProfile.intent`，保留其他 frontmatter 值和逐字节正文；独立旁白写入 `adv/audio/voice-profiles.json`。实际变化才递增字典／旁白文档版本，相同词条不产生无意义写入。

语言必须为规范 BCP 47；词条不能重复，也不能包含 SSML、模板变量或非字面控制内容。作者不能由此建立新的供应商绑定、授权记录、VoiceTake 或 Catalog 回执。保存只创建新候选和修订决定，保留原版本及费用；选定仍遵守现有后续任务与预算约束，正式写入另经统一里程碑审阅。服务重算转换并与不可变产物逐字节匹配，不接受任意文件补丁。

`voice-settings` 审阅权限与真实媒体的 `voice-take` 独立。源工作区可以在编译校验后写入有限词典／意图，不因此获得媒体采用权限。词典和声音意图可同事务采用、重开、恢复回执和条件撤销；新方案含这些变换时，必须先采用，再核对与导入使用对应词典／音色版本的配音。台词、词典与 Profile 变化仍使历史 take 过期，原媒体和账本历史保留。

## 全部对白的配音清单

制作组可只读检查已保存项目当前语言的全部编译对白与独立旁白，覆盖章节 Markdown 和原生 Flow，包括方案未列出的台词及尚无账本行的台词。结果绑定完整源版本，展示稳定 `lineId`、实际源路径、可用行号及运行时地址；缺少或歧义的稳定身份明确标为待处理，不猜测行号。搜索／状态筛选不修改项目。

清单复用既有账本审阅与 Profile／词典过期逻辑，区分缺配音、已有候选尚未选用、选用过期、选中媒体缺失／损坏、字节匹配及身份不明确。对实际选用文件重新核对大小和 SHA-256，不以 Catalog 元数据存在代替原始字节可用；“字节匹配”不表示试听、解码或表演品质通过。缺少可用音色单独提示，标准链接将稳定说话者／台词交给既有任务和审阅页面。

没有目录时也能列出缺失对白；账本无效则明确失败。编译错误下的可编译节点只能显示为不完整清单，不能宣称覆盖全部源。检查期间源文件或账号变化时丢弃结果，不写执行成功记录。它是当前语言的静态清单，不是试玩执行报告，也不表示所有翻译语言已完成。

台词映射必须同时匹配编译后节点类型、源路径、源位置、说话者和完整显示文本。标准 `@speaker` 两行对白的编译源位置指向指令行，方案指向下一行文本；二者须由同一个真实节点与源文本文字对应。不以人物名或数组下标猜测身份。缺少、歧义或暂不支持的源位置拒绝导入；标准 `> 旁白` 使用独立 narrator 配置；普通文本不冒充旁白节点。Flow 的默认源映射没有物理行号，按上述稳定 ID 映射到实际编译节点；旧行号方案继续拒绝猜测。多行 Markdown 则按完整源块和实际编译跨度核对；整部作品的媒体覆盖仍须独立验证。

只接受已选定／已采用且来源未变化的方案；在途任务、未知结算、待恢复文字里程碑阻止新写入。导入前重新读取项目，并在锁内核对全项目源版本、方案身份与逐文件原始字节。切换账号／项目／制作组后丢弃迟到结果。

## 真实音频与来源

首个回流入口接受 WAV：最多 32 MiB、120 秒、双声道，原始采样率 8–192 kHz。校验 RIFF／WAVE、分块边界和格式采样信息，通过真实浏览器 `decodeAudioData` 检查音频、时长和声道，限制解码后样本数为 24,000,000，并计算原始字节 SHA-256。文件扩展名和 MIME 不替代字节检查。解码不启动播放，浏览器音频上下文在完成或失败后关闭。

作者必须选择该说话者／项目语言已有的真实 `system` 或 `recorded` 音色绑定，并记录实际制作来源与使用说明。供应商、模型、实际 voice ID、来源类型、VoiceProfile 指纹来自项目绑定；不允许任填一个托管供应商来冒充服务回执。不支持从此入口导入 cloned／designed 服务结果，已有受信宿主流程继续负责这些候选。既有 rights 需完整保留并要求项目中的同意记录存在。

复用项目现有发音词典和台词 `spokenText` 覆盖、`createVoiceTakeEditPlan`、`serializeVoiceLedger` 与 `planAdvAssetManifestUpsert`。记录方案 ID、表演指示、制作说明和原始字节指纹；唯一目标是标准资源目录和 `adv/audio/voice-ledger.json`，不建立另一本配音账本。

## 审阅、登记和独立采用

审阅展示真实时长、原始采样率、字节数、SHA-256、来源与每个文件的完整前后内容；此时正式项目不变。已审阅候选和原始 WAV 现在先保存到私有持久化日志，刷新后可继续审阅；共享恢复协议见[媒体中断恢复规格](./2026-10-27-studio-creative-media-recovery)。

服务声明 `authoring.mediaCandidates` 后，确认“登记制作组候选（项目未变）”先持久化原请求与幂等键，再创建服务端不可变媒体产物，不写正式项目。未知响应用原请求重试。统一里程碑负责审阅、实际写入媒体／Catalog／账本、恢复和条件撤销；`selectedTake` 保持不变。复用项目锁、全版本检查、逐文件 CAS、持久化屏障和写后报错回滚；原始媒体不可覆盖。写前和写后均从实际编译项目核对稳定台词、当前音色与词典／spokenText 结果、输入指纹及授权文件，再解码核对 WAV。不能把冻结台词与后来变化的音色／词典一起采用。

重开只读，不自动再次登记、写项目或生成。审阅过的部分状态可明确继续或恢复，写后确认丢失则重新读取真实文件后同步原回执。服务确认前保留私有 WAV，确认后释放冗余字节，项目原音频保留。旧服务和未带共享登记信息的历史候选保留既有“登记未选配音候选”本机事务与恢复流程。

之后进入既有配音审阅，从真实文件核验字节并试听。制作组的共享路径要求作者独立勾选试听确认，再创建只改变 `selectedTake` 的候选，重新登记并经统一里程碑采用；不重复音频或伪装为另一轮生成。既有音频作者页仍可独立替换或清除选择，这类外部变更不能冒充制作组采用回执。游戏继续读取同一标准 Catalog 和对白账本。改变台词但保留稳定 ID 后，历史 take 保留且显示过期。

既有作者服务的目录初始化、音频编辑／导入及选用现已接入[共同项目事务](./2026-10-27-studio-creative-adoption#既有音频作者入口的共同事务)：核对完整保存来源及媒体字节，读取等待项目写入完成，作用域切换后丢弃迟到结果。内存后端使用隔离视图和完整基线比较，暂存结果不经自动保存发布；非原子后端只补偿可确认仍属于本轮的写入，保留外窗新稿和可能被引用的媒体。复制要求新不可变目标，仅登记已有媒体继续只核验而不复制。两个真实浏览器窗口的实际持久化回归不替代系统目录／Capacitor 真机验收。

## 实际验证与边界

一段中文对白“列车还没有到，我们再等一会儿。”由本机 `/usr/bin/say`、已安装 Tingting 声音、175 wpm 外部制作，再用 ffmpeg 转为 22,050 Hz 单声道 PCM WAV，人工导入 Studio。这是系统语音真实生成的外部素材，不是人工录音，不是 Studio 托管供应商调用，也不是占位测试波形。

实际文件为 125,740 字节、2.849478 秒，SHA-256 `538922a9bbfe31ecd95ab1f8457041d01bdcb0ae8e007fa0253a25bea1177c3e`。Web Chromium 验证原始字节、审阅前不写项目、未选登记、重开、试听时间推进、独立采用、再次重开、正式 `/tabs/play` 的真实 Web Audio 节点完整时长播放，以及修改台词后过期。对浏览器原生方法只添加观察，不替换解码／播放实现或注入播放结果；记录运行中的上下文、非零目标增益与真实 ended 事件，不声称测量物理扬声器或完成人工表演评分。1280／390px 审阅、采用、游戏画面已留证。

真实语音浏览器回归要求通过 `STUDIO_CREATIVE_VOICE_WAV` 提供上述台词的真实语音文件；没有输入时明确跳过该项，不用测试波形补位。运行示例：

```bash
STUDIO_CREATIVE_VOICE_WAV=/absolute/path/dialogue.wav \
pnpm -C apps/studio exec playwright test \
  --config tests/e2e/creative-team.playwright.config.ts \
```
