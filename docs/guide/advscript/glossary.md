# 对话术语与脚注

在对白中引用术语，玩家可以打开解释，然后回到原来的对白。标准项目复用已有的 `adv/glossary.md`；Editor 的素材面板继续编辑同一份文件。

## 写给玩家的解释

已有术语表格、世界观笔记和备注属于作者资料，不会自动变成玩家词典。需要公开的内容使用 Markdown 脚注定义明确声明：

```text
# 术语表

这里仍可保留作者备注和原来的术语表格。

[^星之记忆]: 每个人心中封存的一段**关键记忆**。

    *记忆并不总是可靠。* 记录在 `memory` 变量中。

    - 通过剧情找到线索
    - 重新阅读相关对白

[^星见市]: 一座靠海的小城。
```

在章节的 `.adv.md` 对白中引用：

```md
@小雨
你听说过星之记忆[^星之记忆]吗？我们可以去星见市[^星见市]寻找线索。
```

玩家看到带下划线的 `[星之记忆]`、`[星见市]` 按钮。鼠标点击或用 Tab 聚焦后按 Enter／空格打开解释；关闭按钮或 Escape 返回对白，焦点回到原引用。打开与关闭不会推进剧情。自动播放和快进在解释打开期间暂停，关闭后按原模式继续。

解释支持段落、**粗体**、_斜体_、行内代码、有序／无序列表及嵌套列表。标题与正文左对齐，长内容可在窗口内滚动；旧版本的纯文本解释继续显示。

渲染使用受限的 Markdown 节点，不插入原始 HTML。链接只保留文字、图片只保留替代文字，不生成可点击链接、不加载图片，也不执行 HTML 或脚本。标题、引用块、代码块等未支持的块结构保留为普通文字；复杂程度超出限制时回退到纯文本。

不要把秘密放在任何会被引用的定义里。标准项目的预览与导出只投影章节实际引用的安全内容，作者源文件保持不变；未引用定义（包括嵌套定义）、术语表格、作者备注、链接及图片的目标地址不会随术语投影发布。代码样例里的 HTML 和链接字符只作为文字显示。

## 章节内定义

单文件故事也可把脚注定义放在同一个章节末尾：

```md
@向导
这是星见市[^city]。

[^city]: 一座靠海的小城。
```

章节内定义只属于该章节；其他章节需自行定义或使用 `adv/glossary.md` 中的公共定义。重复引用同一 ID 会使用同一条解释。ID 按 Markdown 规则忽略英文大小写，支持中文，不可包含空格或换行。

同一章节内重复定义，或章节定义与公共定义重名，都会报错，不会悄悄覆盖。缺失或空解释也会阻止程序生成。把共享定义放在 `adv/glossary.md` 一处即可，不要再复制到章节里。

## 范围

- 支持普通对白文字和不带角色的正文中的脚注引用，包括强调文字中的引用
- 不改变选择、章节跳转、存档格式或变量；读档后仍可重新打开解释
- 不自动匹配术语表格，不建立第二份词典，也不保存“已发现术语”列表
- 旁白引用块、选项标签、标题以及 Flow 自定义节点不是这一版的术语入口
- 共享文件适用于标准项目的 Editor 预览、独立项目预览与项目导出；直接加载旧式公开 Markdown URL 的宿主应使用章节内定义，或先走标准项目投影

程序继续保留纯文本 `definition`，有格式的解释额外携带经过验证的 `definitionContent`。纯文本程序不增加该字段；格式内容变化仍会按现有规则改变程序哈希。安全节点最多 1024 个、深度最多 12 层、文字最多 100000 个 UTF-16 代码单元，超限回退纯文本，不截断成部分富文本。

公共 API `compileMarkdownProgram` / `createAdvMarkdownRuntime` 也可传入 `glossary` 字符串作为作者端输入；客户端只应接收已经投影过的章节内容，不要把原始作者资料作为公开 URL 提供。
