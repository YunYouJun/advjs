# 官方插件目录

Editor 底部「插件」面板包含原有 UI 插件管理和官方供应商目录。目录首批收录 ADV.JS 维护的 Breeze、Qwen MLX 与 OpenAI TTS 适配器，提供能力、平台和资源要求、源码接入步骤及项目状态检测；它们复用「音频」创作界面，不各自增加一套工作台。

目录是维护者登记的静态元数据，不是远程代码安装市场。当前这些作者侧集成通过源码构建与本地链接使用，不提供公共 npm 安装按钮，不自动创建 Python 环境、下载权重、加载模型或调用合成。UI 插件的打包、启停与权限边界见 [Editor UI 插件](./ui-plugins)。

## 首批音频适配器

| 适配器        | 能力                                                         | 平台与准备                                                                                                                         |
| ------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Breeze TTS 2  | 中文描述音色、授权参考克隆、情绪指令，可选逐字对齐           | 本轮验证 Apple Silicon Mac 与本地 Xinference；BF16 权重约 7.63 GB，验收设备为 32 GB 内存，不承诺最低配置；可选对齐权重另约 1.28 GB |
| Qwen3-TTS MLX | 多语言描述音色或授权参考克隆，取决于 VoiceDesign / Base 模型 | 仅 Apple Silicon macOS，需 uv 与隔离 Python 3.12；BF16 1.7B 加 tokenizer 约 4.5 GB，建议预留 16 GB 以上统一内存                    |
| OpenAI TTS    | 内置音色、多语言，支持的模型可使用风格指令；不提供克隆       | Node 宿主可在 macOS / Windows / Linux 使用；需要联网与可用账号，无需本地模型权重                                                   |

以上为适配器能力与已记录的部署条件，不是音质或跨平台一致性的保证。项目实际配置的模型、参考模式及可选对齐能力仍由可信供应商对象声明。

## 源码构建与项目链接

先取得包含本功能的 ADV.JS 源码。共享包、CLI、Editor 和适配器应来自同一个 checkout；仅链接插件到旧版已发布 CLI 不能保证新接口兼容。下面用 Breeze 举例，把所有绝对路径换成实际目录：

```bash
cd /absolute/path/to/advjs
pnpm install
pnpm build:advjs
pnpm editor:build
pnpm --filter @advjs/plugin-breeze-tts build

cd /absolute/path/to/game
pnpm add -D "link:/absolute/path/to/advjs/plugins/plugin-breeze-tts"
```

然后按插件 README 将工厂、JSON 预设和供应商路由合入项目 `adv.config.ts`。Breeze 需要预先启动本机 Xinference 并加载模型；Qwen 的环境准备需显式执行 `adv voice setup`；OpenAI 的凭证只放在可信宿主中，不写入剧本、预设或玩家配置。

使用同一源码的 Node CLI 打开项目：

```bash
node /absolute/path/to/advjs/packages/advjs/bin/adv.mjs editor /absolute/path/to/game
```

Qwen 和 OpenAI 的完整源码接入步骤分别位于各自 README；目录中的「要求与源码接入」也展示对应包的实际构建与 `link:` 命令。链接包不会自动把工厂写入配置，不等于已经准备运行环境或模型。

## 状态检测

打开目录只读取已验证供应商注册表中的 ID、启停状态、声明能力与是否提供 `doctor`；不会执行诊断、扫描模型目录或启动推理。点击某一供应商的「检查状态」后，可信 Node 宿主才调用同一个 `adv voice doctor` 协议，最多等待 20 秒。

- **未连接状态接口**：当前工作区没有 Node 检测端口。使用 `adv editor` 打开本地项目；纯浏览器目录访问不自动获得本机 Python 权限。
- **项目未配置**：项目尚未注册该供应商；不能由这个状态推断 npm 包是否存在。
- **项目已停用**：该项目的供应商状态已停用，检查不会绕过它调用插件；可到「音频 → 供应商与清理」管理。
- **未提供检测接口**：供应商没有 `doctor`，不伪造就绪结果。
- **尚未检查 / 正在检查 / 检查未完成**：分别表示未运行、执行中或失败，可重新检查。
- **当前平台不支持 / 尚未就绪 / 检查通过**：沿用供应商返回的支持与就绪判断，不代表声音质量已验收。

Breeze 检查本地服务中配置的模型是否已加载，不证明实际权重修订；Qwen 检查环境与运行时，生成时才校验选定权重。OpenAI 的只读诊断只检查凭证配置，**不验证远端服务、账号权限或额度，也不报告合成已就绪**。

诊断响应只包含有限检查 ID、状态和固定说明，不包含供应商原始异常、输出、环境路径或凭据。离开面板、切换项目与卸载组件会取消请求，旧项目的迟到结果不会成为新项目状态。刷新项目配置会清除旧的检查结果。

## 维护目录

目录元数据集中在 `editor/core/app/extensions/official-plugins.ts`；新增条目需说明真实能力、已验证平台、准备条件、源码路径和接入方式，不能把未发布适配器标成可从公共注册表安装。实际检查通过 `ProjectWorkspace.voiceProviderStatus` 和认证 bridge 复用 Node 供应商注册表，不按目录 URL 下载或执行代码。

缓存、环境、模型的按需清理继续使用 [语音资源维护](../authoring-voice#停用卸载与可选清理)，参考录音及已生成配音默认保留。目录展示与 npm 发布、模型部署、生成、审核选用是分别执行的操作。
