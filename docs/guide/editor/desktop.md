# Electron 桌面创作客户端

ADV.JS Editor 桌面客户端复用 AGUI Editor，主进程负责原生目录选择、窗口和项目服务。已安装的客户端可直接打开本地项目进行创作，无需安装 Node.js 或 pnpm。macOS arm64 的功能验收见[桌面验收报告](../../reports/electron-desktop-acceptance)，多平台打包流程与本次实际验证见[桌面发布验证记录](../../reports/desktop-release-ci)。

## 打开与编辑

空窗口使用中央欢迎页，点击「创建示例项目」可创建「你好，ADV.JS」入门工程，直接复用仓库 `demo/starter` 的剧本、人物数据和本地图片。示例包含向导小云的头像与三章故事，可体验同章和跨章分支、回看循环、变量与条件选项，以及两种结局；在「流程图」中可以查看全部节点或筛选章节，并定位对应源码。进入项目之前，创建表单会分别确认游戏名称、文件夹名称与存储位置，并显示完整项目路径；创建完成后直接进入编辑工作区，在「游戏」面板启动预览即可运行，无需联网下载素材。人物头像位于 `public/img/characters/xiaoyun.webp`，人物卡片中的 `avatar` 指向该文件；`adv.config.json` 的 `showCharacterAvatar` 控制是否显示。

默认存储位置为系统文档目录下的 `advjs-projects`，macOS 通常是 `~/Documents/advjs-projects`；「更换…」调用原生目录选择器，之后记住上次成功创建的位置。文件夹默认使用简短英文名，同名路径存在时建议添加数字后缀。推荐游戏显示名使用作品原语言，例如「雨夜来信」，文件夹使用 `rainy-letter`；中文文件夹也支持。显示名独立保存为游戏配置的 `title`，修改显示名无需重命名目录。确认「创建并打开」之前不会写入项目，取消创建或取消目录选择均保留当前项目。

无头像、关闭头像或头像加载失败时，人物名称移到正文上方，字号随阅读设置变化。「雨夜来信」仍可从系统菜单的新建项目子菜单创建；已经创建的工程不会自动覆盖或替换。

也可选择 Markdown 创作模板或空白项目；空白项目从一个 `.adv.md` 章节开始。系统「文件 → 新建项目」提供相同模板。项目文件夹必须使用新名称，创建操作不会覆盖已有目录。已有项目中新建会打开新编辑窗口，空窗口中新建则使用当前窗口。

启动 `ADV.JS Editor.app`，点击「打开项目」或使用 `⌘O`，选择含 `adv.config.json` 或 `adv.config.ts` 的项目目录。最近项目记录保存目录路径，每次启动重新建立服务和凭据。取消选择或打开无效目录不会替换当前项目。

未打开项目时，欢迎页显示「最近打开的项目」，包含名称、目录路径和最近打开时间，可按名称或路径搜索。已打开项目带有文字提示，点击后聚焦对应窗口；其他项目直接重新打开。已有项目时，可通过「文件 → 最近项目」或底部「切换项目」打开其他项目。最近打开的项目排在最前，桌面端最多保留 12 个，退出重开后继续保留；同一目录不会重复记录。首页的移除按钮只清理历史记录，不删除项目文件。浏览器版同样支持最近项目，最多保留 10 个目录；访问权限过期时需要点击授权。

打开项目、预览、导出及其他运行错误通过右下角全局通知展示，提供「复制信息给 AI」与「查看日志」。通知位于状态栏上方，关闭后仍可从控制台和状态栏任务详情查看。启动失败、项目恢复等需要原位重试的界面继续提供「复制错误信息」。复制内容包含错误详情、可用的堆栈、项目、版本、运行环境与相关日志，可直接粘贴给 AI 排查。控制台还支持复制单条错误或当前筛选出的日志。剪贴板写入成功后才显示「已复制」；浏览器拒绝访问时，可在展开的文本框中手动复制。项目服务凭据与报告中的常见密钥字段会替换为 `[redacted]`。

macOS 客户端的菜单位于系统顶部。项目文件夹名显示在原生标题栏，未保存时带有标记；窗口内不再保留顶部项目状态行或错误日志区。底部状态栏显示项目连接、保存状态、当前文件、光标位置及构建结果，点击任务可查看日志、取消构建、显示导出结果或复制错误。系统菜单提供打开／最近项目／重新连接／保存／关闭、项目设置、角色管理、Codex 创作工作流、扩展与布局、游戏预览及 Web／ZIP 导出；`编辑 → 偏好设置…`、原 `ADV.JS Editor → 偏好设置…`（`⌘,`）和「关于」在角色等页面也可打开。主题位于「偏好设置 → 主题 → 主题预设」，支持跟随系统、亮色、暗色；跟随系统会实时响应系统外观变化。菜单文字随语言选择更新；剪切、复制、粘贴等使用系统标准行为。扩展操作从「视图 → 编辑器扩展」打开的插件面板进入。Web Editor 保留窗口内的菜单栏。

客户端使用一个主进程管理多个编辑窗口，一个项目对应一个窗口。空窗口直接载入项目；已有项目默认在新窗口打开，可通过「文件 → 在当前窗口打开项目…」或项目切换器的对应操作替换当前项目。`⌘⇧N` 新建空窗口，`⌘⌥O` 打开项目切换器；其中同时显示「已打开」与「最近使用」。选择已打开的项目直接聚焦它，符号链接会解析成真实路径，同一路径只保留一个可写会话。

每个窗口独立持有项目服务、凭据、草稿、构建任务与沙箱预览。布局、激活面板、当前打开的文件及各文件的光标／滚动位置按项目真实路径保存到应用 userData 的 `workspace-state/`，不依赖临时端口；关闭或替换前等待状态保存，重开时恢复。当前文件编辑器为单文档区域，不新增多文件标签界面。退出前先检查所有窗口，任一项目取消或保存失败时均不关闭其他窗口。

首次选择语言或跳过引导后，客户端会记住选择；切换项目、刷新窗口及退出重开都不会再次要求选择。以后可在偏好设置的「界面 → 语言」修改。语言与引导完成状态保存于应用 userData 下的 `editor-preferences.json`，独立于项目与本地服务端口；Web Editor 继续使用浏览器存储。加载页采用内联 SVG Logo，提示文字跟随所选语言；背景、文字与进度条复用 AGUI token，和主编辑器一起切换亮暗主题。

开屏进度与实际初始化任务关联：恢复语言偏好、启用编辑器模块、连接并读取项目文件及场景资源映射。计数表示已完成阶段，不代表下载字节；任务完成才推进进度，全部完成后进入工作区，没有固定等待时间。读取失败会显示原因，可点击「重试」继续失败阶段。直接打开角色等页面也会先完成初始化；没有项目时无需加载项目资源。游戏的大型图片和音频继续按需加载。

JSON/Markdown 项目可编辑 `.character.md` 角色、正文描述、别名、关系和立绘。图片与项目音频导入会复制真实二进制文件到项目资源目录，并更新 `adv/assets.json` 或现有 includes 分片。文件名使用新 ID，避免覆盖共享资源；移除引用保留二进制文件，作者可以确认没有引用后自行清理。

系统「故事 → 创建 → 世界观／场景／章节」与 Web Editor 使用同一创建命令。填写名称、标识符并确认项目文件路径后，文件会保存到内容根目录，再打开源码编辑；从角色页面创建也会返回文件面板。已存在的世界观直接打开，重复场景或章节不能覆盖。未保存的源码与角色表单草稿会阻止创建及跳转，详细规则见[剧本编辑器](./script#创建世界观场景与章节)。

项目音频支持名称、描述、BGM／音效／语音用途、播放、暂停与跳转。切换面板会暂停试听；音频库浏览是另一种资源来源。保存到项目文件成功才算保存完成，localStorage 中的创建草稿和面板布局不是项目保存。

`⌘S` 保存当前已登记草稿和打开的源文件。关闭、退出、重载、切换项目、预览和导出遇到未保存内容时，提供「保存并继续／取消」。保存失败会保留草稿并阻止继续。外部修改会刷新项目；写入前检查原始内容，冲突时选择载入外部版本或保留草稿覆盖。外部删除后可明确选择重建草稿文件。

可执行配置需要原生信任确认，配置可访问本机文件。不要打开不信任的项目；配置入口被外部修改后需要重新连接并再次确认。服务停止时选择「文件 → 重新连接项目」，当前窗口中的表单草稿保留。窗口刷新与应用重启只恢复已保存数据。

## 预览与游戏导出

「游戏」面板默认使用「实时预览」，点击「启动预览」直接运行已保存项目。保存剧本、人物、配置或本地资源后自动更新，无需手动执行生产构建；外部编辑器保存的修改也会更新。未保存的草稿不会影响预览，启动前仍会处理未保存内容。内容更新会重新开始当前游戏页面，可用「重新运行」主动重启。

「运行方式」可切换到「构建预览」，用于检查生产构建和导出效果；「重新构建」重新读取已保存项目并重新开始。系统「视图 → 构建并预览」提供同样入口。实时预览和构建预览都支持「预览位置 → 编辑器内／独立窗口」，系统「视图」菜单也提供两个显示入口。切换位置移动同一个游戏视图，不重新加载剧情；关闭独立窗口会移回编辑器。

「游戏」工具栏的 **Vue DevTools** 开关控制实时预览中的 Vue 调试入口，默认关闭，并在切换项目和重启编辑器后记住选择。切换时自动重新运行当前实时预览，游戏进度会重置，无需编辑 `adv.config.ts`。构建预览下开关禁用，游戏导出不包含调试工具。系统「开发者工具」菜单仍独立控制编辑器的浏览器调试工具。

实时预览的文件监听、Vite 缓存和运行数据位于受管理临时副本，不写入项目源码或覆盖原 `index.html`。内容或资源错误通过全局通知显示，保留最后有效画面，修复保存后自动恢复；切换主题包或插件配置时需重新运行。可执行配置被修改时停止实时服务，需要「重新连接项目」并确认信任后再启动。

两种显示方式都使用独立沙箱，游戏不含桌面 preload、Node.js 或创作客户端的项目凭据。编辑器弹窗与菜单出现时，内嵌游戏让出显示区域，关闭后恢复；切到其他面板时隐藏游戏并静音。「停止」或「停止预览」取消启动或构建，关闭游戏、媒体、文件监听、子进程与临时 HTTP 服务。切换项目和退出也会回收预览。

通用游戏菜单沿用三国项目验证过的分工：顶部保留立绘、旋转、音乐、全屏和设置；回看、自动、快进、快速存读档、手动存读档与隐藏界面位于底部文字操作栏。设置中可选择操作栏常驻、自动收起或保持收起，收起时仍可停止自动／快进。游戏菜单使用作品的游戏主题，外围预览控件使用 AGUI。

在「游戏」面板点击「主题」，选择首页布局、菜单按钮或主题配置，即可跳转「文件」面板编辑。默认主题与 Pominis 支持从内置源码创建项目覆盖；已有文件直接打开，未保存内容会阻止切换。创建首页覆盖时也补齐它依赖的菜单覆盖，原始安装包保持完整。项目中的 Vue、样式及主题配置文件会出现在项目文件树中，预览与游戏导出使用这些覆盖。保存 Vue 或 JSON 主题配置后实时更新；新增或删除覆盖会在同一预览地址重新初始化路由与组件优先级。

同一弹窗可填写修改需求，点击「复制主题上下文给 AI」，把相关主题代码与要求粘贴给 Codex 或其他 AI；复制不调用 AI 服务，也不包含项目剧情或凭据。审阅返回代码后，在文件编辑器粘贴并保存。当前 AI 工作台仍是资料概览，此入口提供代码交接流程。第三方主题没有内置源码时，可编辑已有覆盖或主题配置。

「导出 Web 目录」和「导出 ZIP」调用同一 `advBuild`，在受管理项目副本中构建，成功后才交付指定的新目录或 ZIP。已有目标、项目源码目录和应用资源目录会被拒绝。构建期间可取消；失败会显示错误和日志，原项目的 `index.html` 与既有目标保持完整。

导出使用相对资源路径与 hash 路由，ZIP 只含 Web 构建产物。关闭 Electron 后，解压 ZIP 并使用普通静态 HTTP 服务即可运行，例如在解压目录中执行 `python3 -m http.server 8080`，浏览器打开 `http://localhost:8080`。静态服务器属于导出物的运行环境，桌面应用本身不需要系统 Node.js、pnpm、本仓库或开发服务器。

本地图片与项目音频会随导出复制；作者主动引用的远程资源仍是远程依赖，构建日志会列出依赖的远程 origin，离线项目应使用本地资源。桌面构建禁用默认的联网界面音效和示例装饰图片；项目 BGM 与自定义主题保持原有语义，默认主题优先使用项目封面。

## 开发与打包

开发环境需要仓库指定的 Node.js LTS 与 pnpm：

```bash
pnpm install
pnpm desktop:build
pnpm desktop:dev
pnpm desktop:test
pnpm desktop:package
pnpm desktop:make
```

`desktop:build` 编译引擎、静态 Editor 和桌面进程；`desktop:dev` 启动桌面开发宿主，首次缺少产物时自动补齐构建。修改引擎或 Editor 源码后，重新执行 `desktop:build` 再启动；桌面宿主源码会在启动时重新编译。开发宿主使用静态 Editor，不提供界面热更新。

macOS 开发模式使用项目内的 `ADV.JS Editor Dev.app`，系统菜单、Dock 和应用切换器显示开发应用名称。宿主缓存在 `apps/desktop/.dev/`，按 Electron 版本和开发图标复用；开发偏好设置保留原有位置。窗口标题继续使用 `ADV.JS Editor` 或「项目名 — ADV.JS Editor」。

`desktop:package` 生成当前平台的应用目录（macOS 为 `.app`）；`desktop:make` 生成可解压运行的桌面分发 ZIP。这些命令与应用内的「导出 Web 游戏」是不同产物。打包将运行时依赖复制到应用内，并检查可搬移性；应用运行不依赖仓库的 `node_modules`。

macOS arm64 产物在 `apps/desktop/out/ADV.JS Editor-darwin-arm64/ADV.JS Editor.app`，分发 ZIP 在 `apps/desktop/out/make/`。最终验收使用移出仓库的应用副本和受限 PATH，证据位置见验收报告。

```bash
ADVJS_WEB_CHANNEL=chrome ADVJS_DESKTOP_EXECUTABLE="/absolute/path/ADV.JS Editor.app/Contents/MacOS/advjs-editor" pnpm desktop:test
```

### 应用图标

桌面 Editor 保留 ADV.JS 的蓝青色对话框／摄影机标识，采用银白底板与 Liquid Glass 材质。源文件为 `apps/desktop/assets/ADVJSEditor.icon`：对话框与摄影机使用独立、未裁切的 SVG 图层，圆角、边缘光和折射交给系统处理，并提供深色与单色外观。设计遵循 [Apple 应用图标指南](https://developer.apple.com/design/human-interface-guidelines/app-icons)。

仓库只保留 `.icon` 图层、`dev-badge.svg` 和一份无损的 `icon-fallback.webp`，不提交生成的 PNG／ICNS／ICO 或 `Assets.car`。兼容图来自 Icon Composer 的渲染结果，保留原生连续曲率轮廓，并缩入 1024px 画布中央的 824px 区域，以匹配传统 Dock 图标的留白。

桌面构建自动在被 Git 忽略的 `apps/desktop/assets/generated/` 中生成发布与开发图标。macOS 构建检测到 Xcode 的 Icon Composer 时，还会编译 `Assets.car`，并通过 `CFBundleIconName` 引用原生分层图标；没有该工具的构建使用静态 ICNS 兼容图。`icon.ico` 用于 Windows，`icon.png` 用于其他平台的窗口图标。发布版 Dock 和 Finder 读取应用包中的图标。

开发宿主（`app.isPackaged === false`）自动使用带黄色 `DEV` 角标的 `icon-dev.png` / `icon-dev.ico`，覆盖 macOS Dock 及 Windows／Linux 窗口图标；macOS 开发应用包同时使用 `icon-dev.icns`。角标来自 `assets/dev-badge.svg`，直接合入开发图标，不依赖系统通知权限。打包版继续使用无角标图标，不携带开发图标资源。

使用 Icon Composer 修改 `.icon` 源文件及其 `Assets/` 图层后，在安装 Xcode 27 或更新版本的 macOS 上刷新并提交兼容源图：

```bash
pnpm -C apps/desktop icons:source
```

日常构建通过 Sharp 从兼容源图生成静态图标，不需要 Xcode；也可单独运行 `pnpm -C apps/desktop icons`。ICNS 包含 16–1024px 的表示，ICO 包含 16–256px 的七档尺寸。原生资源通过 Xcode 的 `actool` 编译，兼容源图刷新使用 Icon Composer 图像导出器。`.icon` 与静态 `icon.icns` 使用不同文件名，避免 Electron Packager 自行重新编译源文件。资源通过 Forge 一同打包，移动应用目录后仍可读取；配置方式参照 [Electron Forge 图标指南](https://www.electronforge.io/guides/create-and-add-icons)。

## 自动构建与发版

桌面工作流使用每个平台的原生 runner，分别构建以下产物：

| 系统    | 架构  | 分发内容                         |
| ------- | ----- | -------------------------------- |
| macOS   | arm64 | Apple Silicon `.app` ZIP         |
| macOS   | x64   | Intel `.app` ZIP                 |
| Windows | x64   | 含 `advjs-editor.exe` 的便携 ZIP |
| Linux   | x64   | 含 `advjs-editor` 的应用目录 ZIP |

`.github/workflows/desktop.yml` 在相关代码的 PR、`dev`／`main` 推送时执行，也支持在 GitHub Actions 手动运行。工作流构建应用，并从临时目录启动打包产物，打开测试项目、导出 Web 游戏，成功后上传 Actions artifacts。是否支持某个平台，以该平台实际工作流结果为准。

`.github/workflows/release-desktop.yml` 在发布 `v<版本>` 或 `desktop-v<版本>` GitHub Release 时自动构建，正式版和预发布均适用；`core-v*` 不触发桌面发布。四个平台全部成功后，统一把 ZIP 和 `SHA256SUMS.txt` 附加到对应 Release。工作流固定到标签实际指向的提交，打包版本来自标签，不依赖默认分支当时的内容，也不改写源码包版本。补跑同一标签时替换同名附件，以恢复中断的上传。

现有 Release 晋级工作流在正式晋级成功后直接调用桌面发布工作流。这样即使 Release 由 `GITHUB_TOKEN` 创建，也不会因为 GitHub 阻止递归触发而漏掉桌面构建；dry-run 和 abort 不发布客户端。手动补跑可在「Release desktop applications」工作流选择已经存在的 Release 标签。

独立发布客户端时，在包含所需改动的提交上创建 `desktop-v0.1.5` 标签，再为此标签发布 GitHub Release。仅推送标签不会创建公开 Release 或上传附件。发布整套 ADV.JS 时继续使用现有晋级流程。

当前提供未签名的 ZIP，不包含应用内自动更新。升级时退出客户端，下载匹配架构的 ZIP 并替换应用；项目目录与应用偏好设置独立保存。macOS 签名／公证、Windows 代码签名以及 DMG／安装向导属于后续分发工作。

## 验证

本地先执行 `pnpm desktop:make`，确认 `apps/desktop/out/make/` 生成当前版本的 ZIP。然后运行打包验证：

```bash
node apps/desktop/scripts/verify-package.mjs
```

检查 GitHub Actions 中四个平台均通过、Release 附件齐全，并按 `SHA256SUMS.txt` 校验下载文件。完整创作流程回归仍使用 `pnpm desktop:test`；打包验证不能替代所有界面和游戏功能验收。

## 支持边界

- JSON/Markdown 源项目：角色、立绘、项目音频、真实保存、外部刷新、预览和导出。
- 现有 CLI/Vite 项目：信任后的配置加载、预览和导出；内联 TS 配置属于可执行源，结构化编辑器不会自动改写 TS。建议把可视化编辑内容迁入 Markdown 与资源清单。
- 仓库 `demo/starter/vite.config.ts` 包含指向仓库工具的开发 alias，复制该工程用于独立创作时应换成普通独立 Vite 配置（例如 `export default {}`）。验收使用同一份 starter 故事与 ADV 配置，以及这个独立 Vite 配置；原仓库专用配置会报告越界依赖失败。
- ZIP 使用标准 ZIP 格式，最多 65,535 个文件；大于 4 GiB 的项目应导出 Web 目录。
- 打包工具链包含 ADV.JS 默认运行时与默认主题，不自动安装任意第三方依赖或执行安装脚本。自定义主题／插件／配置缺失依赖时构建会失败并报告原因。
- 不包含开发者签名、公证、应用内自动更新或协作账号流程；多平台构建及 Release 附件上传由上述 CI 完成。

Studio 回归同时修复了内存项目的 IndexedDB 二进制持久化；旧版本已经丢失的二进制文件需要重新导入，不影响真实目录项目。

宿主与安全边界在 `apps/desktop/src/`；面板通过 `ProjectWorkspace` 读写项目，保持 AGUI Editor、游戏主题和移动 Studio 的设计边界。
