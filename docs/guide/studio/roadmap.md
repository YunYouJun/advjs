## 后续工作

以下汇总已有验收缺口与规划入口，不新增上线承诺，也不把旧任务自动标为完成。

| 方向         | 需要补齐或持续验证的内容                                     | 完成依据                                                                                          |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 本地核心流程 | 打开项目、角色／立绘／音频编辑、保存恢复、资源刷新及游戏预览 | 同一项目的磁盘或持久化结果、浏览器操作证据和回归报告。                                            |
| 云端流程     | SSO、素材发布、托管 AI 及其失败恢复                          | 对应环境与版本的实际验收；本地 fixture 和 mock 不能替代。                                         |
| 协作与社区   | 真实环境下的双客户端收敛、断线恢复、权限拒绝和发布流程       | 区分确定性测试与真实云端验证，不再维护两份“已完成／未完成”清单。                                  |
| 原生移动端   | Capacitor 项目的文件权限、恢复、媒体及触控流程               | 按平台记录实机结果；Web 通过不等于原生平台已验收。                                                |
| 音频演进     | 统一 AudioEngine 与 AI 配音资产协议                          | 跟随[音频实施计划](/plans/2026-08-12-audio-system-implementation)，保留现有能力与目标协议的区别。 |

桌面 Electron 是 Editor 的独立交付线，任务与状态见 [Electron 计划](/plans/2026-10-06-electron-desktop)，不复制为 Studio 的另一份客户端计划。

## 待条件成熟后启动的方向

- 位置驱动剧情：依赖 Flow 节点系统及项目语义，不将地图原型视为完整创作能力。
- Mystery 角色属性模板：先明确角色字段可见性与视角契约，再扩展模板。
- AI 回填角色属性、图片、TTS 等能力：先完成托管能力登记、协议和提案审阅，再开放产品入口。
- 创作者激励与推送：根据真实运营需求另行立项；保留已有功能，不预建新的积分或复杂通知系统。

## 计划与验收怎么维护

一次交付只维护一份[实施计划](/plans/)；完成目标、任务依赖和验收项放在计划中，实际环境、结果和限制放在 `docs/reports/`。本页只更新方向与入口，避免复制实现清单和容易过期的测试统计。

历史阶段号用于追溯，不是当前版本号或发布承诺。原 Phase、M、N 系列实现记录、赛事待办和旧部署方案统一见[历史资料](/archive/)。
