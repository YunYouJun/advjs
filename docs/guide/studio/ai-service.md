# Studio 托管 AI 与 Editor 本地 Agent

ADV.JS 为在线 Studio 和本地 Editor 采用不同的 AI 产品边界。两者共用开放的项目格式与提案协议，但不共用密钥、运行环境或计费方式。

Studio 的共享 AI Runtime 当前由 `YunLeFun/api` 仓库中的 `services/ai-runtime` 承载，ADV.JS v1 传输兼容层位于同仓库的 `packages/ai-runtime-advjs`。`www.yunle.fun` 只保留冻结的 v1 契约 fixture，不再承载独立 Runtime。

| 产品   | 定位                             | AI 执行位置                                    | 身份与费用                                 | BYOK                 |
| ------ | -------------------------------- | ---------------------------------------------- | ------------------------------------------ | -------------------- |
| Studio | 面向普通创作者的 Web/移动端 SaaS | 云端托管 Runtime                               | 云乐坊 SSO；按 AI 点数预占并按实际用量结算 | 生产版不提供         |
| Editor | 面向专业创作者的本地生产力工具   | Codex、Claude Code、Cursor 等本地 Agent 工作流 | 用户自行选择本地工具或供应商               | 可由本地开发工具管理 |

## Studio 当前开放的能力

Studio 首期只开放五项已经在服务端登记、定价和校验的能力：

- 剧情大纲；
- 章节草稿；
- 情节建议；
- 角色扮演模拟；
- 一致性检查。

发起任务前需要登录云乐坊账号。Studio 只发送当前能力需要的已保存项目文件；服务端决定模型、提示词、安全规则、价格和最大用量。创建任务时会预占 AI 点数，任务结算后按实际用量扣除并释放剩余预占。

大纲和章节草稿生成的是候选提案，不会自动写入项目。用户需要检查摘要、影响文件和 diff 后明确应用；应用后仍可在项目没有继续变化时撤销。一致性检查是只读诊断，不会修改文件。

## 暂未开放的能力

通用聊天、角色聊天、群聊、内容抽取、向量 Embedding、图片生成、云端 TTS、托管 ASR、角色日记和自动世界事件尚未登记为 Studio 托管能力。对应入口在生产版隐藏或关闭，不会回退到浏览器直连第三方模型。

本地关键词检索等不产生供应商请求的确定性能力可以继续使用。场景和角色表单仍可保存或复制图片提示词，但 Studio 不直接生成图片。

## 密钥与隐私边界

Studio 生产版不要求、读取或保存 OpenAI、DeepSeek 等供应商 API Key，也不允许设置供应商、模型或 Base URL。升级时只在本机删除旧版 `advjs-studio-ai` 配置，不读取、解析、记录或上传其中内容。

托管任务会把完成该能力所需的项目片段发送到 ADV.JS 的 AI Runtime，再由服务端选定的模型处理。不要在项目内容中放入不希望提交给托管服务的凭证或秘密。遥测默认关闭，并与 AI 任务数据分开处理。

## 什么时候使用 Editor

以下情况优先使用本地 Editor：

- 希望使用自己的 API Key、模型或本地模型；
- 需要 Codex/Skills/MCP 批量修改大量项目文件；
- 需要离线工作或完整掌控 Agent 上下文；
- 需要 Studio 尚未登记的生成能力。

Editor 不把 BYOK 配置写进 ADV.JS 项目。密钥由所选的本地 Agent 或操作系统环境管理，生成结果仍落到可审阅、可用 Git 追踪的 Markdown 项目文件中。
